# dicom vs IQ



**灰度图像（我们有的）**：

某个像素在 30 帧内的时间序列是这样的（DICOM B 超灰度值，归一化到 0~1）：

```
帧1: 0.42
帧2: 0.45
帧3: 0.38
帧4: 0.51
帧5: 0.44
...
```

$0.42 \to 0.45 \to 0.38 \to 0.51 \to 0.44$，这是一条**单调的亮度变化曲线**。带通滤波看看中间有没有周期波动。

**IQ 复数数据（论文用的）**：

同一个像素在同样 30 帧内的 IQ 值是两个数（实部 I + 虚部 Q）：

```
帧1: 0.30 + 0.28j    → 幅度=0.41, 相位=43°
帧2: 0.32 + 0.30j    → 幅度=0.44, 相位=43°
帧3: 0.27 + 0.26j    → 幅度=0.37, 相位=44°
帧4: 0.35 + 0.40j    → 幅度=0.53, 相位=49°   ← 相位突变！
帧5: 0.31 + 0.29j    → 幅度=0.42, 相位=43°
...
```

注意帧 4：**幅度变化不大（0.37→0.53），但相位突然从 44° 跳到 49° 又跳回来**。单看幅度你会觉得"没什么异常"，但相位告诉你这个像素在这一瞬间被微泡散射信号干扰了。

### 为什么相位信息重要

```
         灰度帧（我们）              IQ 复数（论文）
         ──────────────              ──────────────
         只有 |z| = sqrt(I²+Q²)      I 和 Q 分开存储
         ↓                           ↓
带通滤波: 只滤幅度变化               可以分别滤 I 和 Q
         ↓                           ↓
         丢失了相位中的微泡信息       保留完整的散射体运动信息
```

**微泡的本质**：微泡在声场中震荡，不仅改变回声强度（幅度），更改变回声**到达时间（相位）**。IQ 复数能完整记录这个震荡，灰度帧只能看到亮度起伏——就像看一部电影，有人关掉了声音让你只看画面难度大多了。

### MATLAB .mat 里 IQ 的结构

论文的 akebia_human.m 中：

```matlab
varList = "bubbles";  % 变量名
dataSource = double(matfile(filePath).bubbles);  % 这是一个复数矩阵
% size(dataSource) = [height, width, nFrames]，每个元素是 complex double
```

一个元素的值比如 `-45.2 + 12.7j`，幅度 $|z| = \sqrt{(-45.2)^2 + 12.7^2} \approx 46.9$，相位 $\angle = \arctan(12.7/(-45.2)) \approx 164°$。

我们 DICOM 灰度帧对应的是取 `abs(dataSource)` 或 `20*log10(abs(dataSource))` —— 这就是丢失相位信息的"去掉一半信息"的版本。

### 能不能从 DICOM 恢复 IQ？

**不能。** DICOM B 超帧是 $|IQ|$ 经过**对数压缩 → 扫描转换 → 8-bit 量化**的最终显示图像，这些步骤都是不可逆的。要得到 IQ 数据，必须在超声机导出时选择原始波束合成数据格式（`.mat`、`.iq`、`.bf` 等）。









# step1与论文方法之对比

Akebia human 的 Step1（对应 `BlockInterp2Track` + `ULM_localization2D_interp`）是这样做的：

### 完整流程

```
IQ 复数 [H,W,T]          ← 插值后的复数矩阵，比如 -45.2+12.7j
    ↓
1阶 butter 带通         ← filter() 直接对复数时间轴滤波
（可选，仅 Rapid 用）     实部和虚部分别被滤波，相位信息保留
    ↓
逐帧：imgaussfilt(复数)  ← MATLAB 对复数做高斯平滑时，
    ↓                     自动分离实部/虚部，分别平滑后重新合成复数
imregionalmax(复数)     ← 对幅度（|z|）求局部极大值
    ↓
阈值 100 dB             ← 也是和幅度比较
    ↓
存储该位置的复数原始值    ← frame(isABubble)，保留的是完整的复数
```

### 关键发现：他们用到了幅度做检测，但保留复数做追踪

```
论文的"检测": 用 |z|（幅度）判断是不是微泡
论文的"追踪": 用 z = I + jQ（复数原始值）传给 SimpleTracker
```

所以对比我们：

|                  | Akebia Step1                 | 我们的 Step01                       |
| ---------------- | ---------------------------- | ----------------------------------- |
| **滤波对象**     | IQ 复数（I/Q 分别滤）        | float32 灰度（只有幅度）            |
| **检测依据**     | 高斯平滑后的 ‖复数‖ > 100 dB | signed bandpass 取正后 > 均值+N×std |
| **传给追踪的值** | 复数原始值（有相位）         | signed bandpass 值（只有实部）      |

### 相位在追踪环节有什么用？

论文把复数原始值传给追踪器后，相邻帧的**相位差**可以反映微泡的**精确运动**。比如：

```
帧5 某像素: -45.2 + 12.7j  (相位 164°)
帧6 同轨迹: -43.8 + 14.1j  (相位 162°)
→ 相位变化 2°，对应微泡向探头靠近了 ~0.004 mm
```

我们只有实数值，丢失了从相位推断微小位移的能力。

### 但我们不是必须用 IQ

论文虽然保留复数传给追踪器，但人类链路的**定位精度是像素级**（`imregionalmax` 不返回亚像素），并没有用到相位做亚像素定位。相位优势在**大鼠链路的径向对称法**才真正发挥。对人类链路来说，**用复数 IQ 的收益主要在滤波阶段的时域信息更丰富**，对定位精度本身影响不大。

## 对比

论文的"Step2"不是在单独一个脚本里，**高斯平滑 + 峰值检测 + 阈值判定**全被合并到 `BlockInterp2Track` → `ULM_localization2D_interp` 里。

```
论文:  IQ复数 → 1阶butter(可选) → imgaussfilt(复数) → imregionalmax → dB阈值 → 定位
我们:  灰度帧 → 3阶sosfiltfilt → step02: gaussian_filter(实值) → step03: np.maximum(取正) → peak_local_max → 自适应阈值
```

### 详细对比

|                      | Akebia `ULM_localization2D_interp`                           | 我们的 Step02 + Step03                           |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------ |
| **高斯对象**         | IQ **复数**矩阵（`imgaussfilt` 分别对实/虚部平滑，再合成复数） | signed bandpass **实值**（`gaussian_filter`）    |
| **sigma**            | 1.0                                                          | `GAUSSIAN_SIGMA = 1.0` ✅ 一致                    |
| **检测方法**         | `imregionalmax`（全域局部极大值）                            | `peak_local_max`（带 `min_distance=3` 间距约束） |
| **阈值**             | 固定 100 dB                                                  | 自适应：`mean + PEAK_THRESHOLD_STD × std`        |
| **平滑 vs 检测**     | **合并**在同一函数                                           | **拆分**到 step02/step03（中间结果可检查）       |
| **输出传给追踪的值** | 复数原始值（IQ 信号本身）                                    | signed bandpass 值 + 正向响应强度                |

### 关键差异点

1. **复数 vs 实值高斯平滑**：论文对 IQ 复数做 `imgaussfilt`，MATLAB 对复数自动分离实/虚部。我们只对实值做 `gaussian_filter`。复数平滑能保留更多相位结构信息。

2. **`imregionalmax` vs `peak_local_max`**：论文用 `imregionalmax` 找**所有**大于邻居的局部极大值，不做间距约束，所以密集区域可能出很多候选。我们加了 `min_distance=3`，防止同一微泡被反复检测。

3. **固定阈值 vs 自适应阈值**：论文阈值固定 100 dB，来自 IQ 复数幅度的 dB 标度。我们的阈值自适应 `mean + N×std`，更适合灰度帧的动态范围。

4. **复数原始值传递给追踪器**：这是关键 —— 论文把复数原始值而不是平滑后的值传给 SimpleTracker，复数保留了相位（相邻帧相位差反映微泡微小运动）。我们只保留 signed 实数值。

### 对我们 Step02 的建议

Step02 本身只做高斯平滑、不做检测，和论文思路一致（都是 Gaussian 降噪后再找峰值）。主要差距在第三步（检测 + 被传到追踪的值），不是 Step02 的问题。可以关注：如果把 Step03 的 `min_distance` 调小让更多候选进入追踪，或者换个更接近 `imregionalmax` 行为的检测策略。







# Step3与论文方法对比

我们项目的 gap-closing（`_gap_closing_merge`，见 ulm_tracking.py）：

- 对所有轨迹尾端点的帧号 `end_frame`，向后搜索 1~`MAX_GAP_CLOSING_FRAMES` 帧内其他轨迹的首端点（`start_frame ≤ end_frame + max_gap`），如果距离 ≤ `MAX_FRAME_DISPLACEMENT_PX` 就用最近邻合并，中间缺失帧补 NaN。

Akebia SimpleTracker 的 gap-closing（simpletracker.m）：

- 仅对**匈牙利匹配后仍未匹配的**源点 `unmatched_sources{i}` 和未匹配的目标点 `unmatched_targets{j}`，对每一帧 `i` 向前看 `i+2` 到 `i + max_gap_closing` 帧，用 `nearestneighborlinker` 连接距离 ≤ `max_linking_distance` 的点，在邻接矩阵中添加跨多条帧的边。

关键区别：  
1. 我们用的是所有轨迹的尾/头，而 Akebia 只对“匈牙利没配上的”尾/头做 gap-closing。  
2. 我们用的是最近邻配对，Akebia 也用最近邻，但两者实现细节不同（我们是单次遍历，Akebia 在邻接矩阵中逐帧重复配对）。  
3. 我们都支持跨多帧桥接（`MAX_GAP_CLOSING_FRAMES` vs `max_gap_closing`）。  
4. 我们的源码里没有显式“禁止已用点”的标记，Akebia 会跟踪 `unmatched_targets` 避免重复使用。我们项目的 gap-closing（`_gap_closing_merge`，在 ulm_tracking.py 中）：

- 对所有轨迹尾端点的帧号 `end_frame`，向后搜索 1~`MAX_GAP_CLOSING_FRAMES` 帧内其他轨迹的首端点（`start_frame ≤ end_frame + max_gap`）。  
- 如果距离 ≤ `MAX_FRAME_DISPLACEMENT_PX`，用最近邻合并，中间缺失帧补 NaN。

Akebia SimpleTracker 的 gap-closing（simpletracker.m）：

- 仅对**匈牙利匹配后仍未匹配的**源点 `unmatched_sources{i}` 和未匹配的目标点 `unmatched_targets{j}`。  
- 对每一帧 i，向前看 `i+2` 到 `i + max_gap_closing` 帧，用 `nearestneighborlinker` 连接距离 ≤ `max_linking_distance` 的点，在邻接矩阵中添加跨多条帧的边。

关键差异：
1. 我们扫描的是“所有轨迹尾→头”，不限于未被匈牙利配对的那部分；Akebia 只对匈牙利未配对的尾/头做桥接。
2. 我们都使用最近邻配对，且都支持跨多帧。
3. Akebia 会标记已用的目标点防止重复连接，我们的实现目前没有显式防止同一头部被多条尾部桥接（后续会靠“清空被合并的轨迹”来间接避免，但并非像素级去重）。
