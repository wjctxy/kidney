# Human Step 04 速度分组、密度图与指标说明报告

本文说明当前项目中 Human Step 04 的具体功能、实现逻辑，以及生成的高速/慢速 PNG 图像和 CSV 文件分别代表什么。本文只解释当前代码和当前样例输出，不修改算法逻辑。

## 1. Step 04 在整条链路中的位置

Human 链路当前为：

```text
Step 00 DICOM 预处理
    -> frames.npy, metadata.json

Step 01 时域带通滤波
    -> human_filtered.npy

Step 02 高斯滤波
    -> human_smoothed.npy

Step 03 正向峰值检测 + 匈牙利轨迹追踪
    -> human_detections.csv
    -> human_tracks.csv

Step 04 速度分组 + 密度图重建 + 轨迹指标统计
    -> high/low speed tracks
    -> density PNG
    -> metrics CSV
    -> summary TXT
```

Step 04 不再重新做微泡检测，也不再重新做匈牙利匹配。它的输入已经是 Step 03 生成好的轨迹点表 `human_tracks.csv`。因此 Step 04 的核心任务是：

1. 读取轨迹点。
2. 按每条轨迹的平均速度分成低速组和高速组。
3. 将轨迹点累计到超分辨率网格，生成密度图。
4. 为每条轨迹计算路径长度、持续时间、平均速度等指标。
5. 输出分组后的 CSV、密度 PNG 和汇总 TXT。

## 3. 速度分组逻辑

速度分组实现在 `ulm_tracking.py` 的 `_split_tracks_by_speed()`。

对每条轨迹，代码取除第一个点以外的所有速度：

```python
velocities = [float(p["velocity"]) for p in track.points[1:]]
mean_velocity = np.mean(velocities)
```

第一个点的 `velocity` 通常为 0，因为它没有前一个点可用于计算速度，所以分组时排除第一个点。

分类阈值来自 `ulm_config.py`：

```python
SPEED_THRESHOLD = 1.0
```

分组规则：

```text
mean_velocity >= 1.0 -> high speed
mean_velocity <  1.0 -> low speed
```

注意：这里的高低速是相对当前算法和当前物理标定而言的分组，不等同于医学上已经验证的动脉/静脉/毛细血管分类。

## 4. 速度的计算方式

轨迹点速度由 Step 03 生成，计算函数为 `ulm_tracking.py` 中的 `_velocity()`：

```text
dt = t1 - t0
dx = x1_physical - x0_physical
dy = y1_physical - y0_physical
velocity = sqrt(dx^2 + dy^2) / dt
```

当前 metadata 中 `fps = 30 Hz`，相邻帧时间间隔约为：

```text
1 / 30 = 0.033333 s
```

如果两个点之间跨过缺失帧，`dt` 会相应变大。因此速度不是简单的像素距离，而是物理距离除以实际时间间隔。

## 5. 密度图生成逻辑

密度图生成实现在 `ulm_tracking.py` 的 `_density_from_tracks()`。

### 5.1 超分辨率网格

原始 ROI 尺寸为：

```text
height = 590
width  = 602
```

超分辨率倍数来自 `ulm_config.py`：

```python
SUPER_RES_FACTOR = 4
```

因此输出密度图尺寸为：

```text
590 * 4 = 2360
602 * 4 = 2408
```

当前生成的 PNG 图像尺寸均为：

```text
2360 x 2408 x 3
```

### 5.2 轨迹点累计

对每个轨迹点：

```text
x_super = round(x_pixel * 4)
y_super = round(y_pixel * 4)
density[y_super, x_super] += 1
```

也就是说，密度图表示的是轨迹点在空间上的累计出现次数。某个位置越亮，说明该位置附近被轨迹点经过的次数越多。

### 5.3 高斯平滑

累计完成后，如果密度矩阵非空，会做一次高斯模糊：

```python
cv2.GaussianBlur(density, (0, 0), sigmaX=1.2 * scale)
```

当前 `scale = 4`，所以：

```text
sigmaX = 4.8
```

这一步不是 Step 02 的图像滤波，而是密度图层面的可视化平滑。它的作用是让离散轨迹点形成更连续的血管状结构。

## 6. PNG 图像的颜色和含义

PNG 由 `_write_density_maps()` 输出。

### 6.1 `human_density_total.png`

含义：所有轨迹点的总密度图。

颜色：白色。

解释：

```text
黑色 = 没有轨迹点累计
白色越亮 = 累计轨迹点越多
```

该图不区分快慢速，只反映总体微泡轨迹密度。

### 6.2 `human_density_low_speed.png`

含义：只使用低速轨迹生成的密度图。

颜色：紫色。

解释：

```text
黑色 = 没有低速轨迹点累计
紫色越亮 = 低速轨迹点累计越多
```

低速轨迹定义为：

```text
mean_velocity < 1.0
```

### 6.3 `human_density_high_speed.png`

含义：只使用高速轨迹生成的密度图。

颜色：绿色。

解释：

```text
黑色 = 没有高速轨迹点累计
绿色越亮 = 高速轨迹点累计越多
```

高速轨迹定义为：

```text
mean_velocity >= 1.0
```

### 6.4 `human_density_speed_overlay.png`

含义：高低速合成密度图。

颜色规则：

```text
黑色 = 无轨迹密度
紫色 = 低速轨迹密度
绿色 = 高速轨迹密度
接近白色/浅色 = 高低速密度空间重叠
```

实现方式：

```text
低速密度 -> B 通道 + R 通道 -> 紫色
高速密度 -> G 通道          -> 绿色
```

该图适合直观看高速和低速轨迹在空间上是否分布于不同区域。

## 7. PNG 归一化方式

密度矩阵本身是 float32 累计值，PNG 是为了查看而生成的 8-bit 彩色图。

颜色映射前，代码使用 `_normalize_density_uint8()`：

```text
1. 取 density > 0 的非零像素
2. 计算非零像素的 99 百分位 hi
3. density / hi * 255
4. clip 到 0-255
5. 转为 uint8
```

这样做的原因是避免极少数非常高的累计点把整张图压暗。

需要注意：

1. PNG 的亮度是为了显示，不是原始密度矩阵。
2. 低速图和高速图分别独立归一化，因此两张单独 PNG 的亮度不能直接比较绝对密度大小。
3. 要比较真实数量，应看 CSV 轨迹数量、轨迹点数量，或保存原始 density 矩阵后再比较。

```text

627 条高速轨迹
```

### 8.3 `human_metrics.csv`

该文件是逐轨迹指标表，每行对应一条轨迹。

字段说明：

| 字段 | 含义 |
|---|---|
| `track_id` | 轨迹编号 |
| `point_count` | 轨迹包含的点数 |
| `duration_s` | 轨迹持续时间，单位秒 |
| `path_length` | 轨迹累计路径长度 |
| `straight_distance` | 起点到终点的直线距离 |
| `normalized_distance` | `path_length / straight_distance` |
| `dwell_time_s` | 滞留时间；当前实现等同于 `duration_s` |
| `mean_velocity` | 轨迹平均速度 |
| `max_velocity` | 轨迹最大逐点速度 |
| `dispersion` | 方向一致性指标 |
| `speed_group` | `low` 或 `high` |

`normalized_distance` 可理解为路径曲折程度：

```text
接近 1     -> 更接近直线
明显大于 1 -> 路径更曲折，或存在定位抖动/错误连接
```

`dispersion` 当前实现是方向一致性比例：

1. 计算轨迹中每一步的运动角度。
2. 取角度中位数。
3. 统计有多少步落在中位方向 ±20 度内。
4. 返回该比例。

因此：

```text
dispersion 越高 -> 轨迹方向越一致
dispersion 越低 -> 轨迹方向变化越多
```

虽然字段名叫 `dispersion`，但当前数学含义更接近“方向一致性比例”。

### 8.4 `human_summary.txt`

该文件保存总体摘要：

```text
ULM 轨迹指标摘要
total_tracks: 22449
low_speed_tracks: 21822
high_speed_tracks: 627
mean_velocity: 0.606704
mean_normalized_distance: 5.060608
mean_dwell_time_s: 0.724941
mean_dispersion: 0.228903
```

## 10. 从当前结果可以读出的信息

### 10.1 数量学信息

Step 04 当前可以提供以下数量信息：

1. 低速和高速轨迹各有多少条。
2. 低速和高速轨迹各包含多少轨迹点。
3. 每条轨迹持续了多长时间。
4. 每条轨迹的平均速度和最大速度。
5. 每条轨迹的路径长度和直线位移。
6. 每条轨迹是否较直、较曲折。
7. 高速和低速轨迹在空间上的分布是否重叠。
8. 哪些区域轨迹点累计较多，形成更明显的微血管密度结构。

### 10.2 医学相关信息

这些结果可以作为微血流和微血管灌注的间接量化信息：

1. `human_density_total.png` 可反映总体微泡轨迹密度，间接对应局部灌注活跃程度。
2. `human_density_low_speed.png` 可观察低速轨迹主要分布区域，可能对应较慢流速或较复杂的微循环区域。
3. `human_density_high_speed.png` 可观察高速轨迹主要分布区域，可能对应较快流动通路。
4. `human_density_speed_overlay.png` 可观察高低速轨迹是否沿不同空间结构分布。
5. `human_metrics.csv` 中的速度、路径、持续时间可用于后续和病理、分组、ROI 区域进行统计比较。

### 10.3 当前不能直接说明的医学结论

当前 Step 04 不能直接给出以下结论：

1. 不能直接诊断肾功能正常或异常。
2. 不能直接区分动脉、静脉和毛细血管。
3. 不能直接给出真实血流量。
4. 不能直接给出真实血管直径。
5. 不能直接证明缺血、炎症、坏死或纤维化。
6. 不能单独作为临床诊断指标。

原因是当前只有单个样例，缺少人工标注、对照组、重复样本、ROI 分区统计和临床/病理标签。

## 11. 使用这些输出时的注意事项

1. 高速/低速分组依赖 `SPEED_THRESHOLD = 1.0`。如果阈值改变，分组数量和图像都会改变。
2. 速度依赖物理像素尺寸和 fps。如果 DICOM metadata 或像素标定错误，速度统计也会偏移。
3. PNG 是可视化结果，不是原始定量矩阵。
4. 低速图和高速图分别做 99 百分位显示归一化，不能仅凭亮度直接比较绝对数量。
5. 高速轨迹数量当前明显少于低速轨迹，因此高速图在空间上更稀疏是合理现象。
6. `normalized_distance` 极大值可能来自定位抖动、短轨迹、错误连接或往返运动，解释时需要结合原始轨迹检查。
7. 当前 `dispersion` 字段实际更接近方向一致性比例，字段名和数学意义需要在正式论文/报告中明确说明。



我按 **`SPEED_THRESHOLD = 1.0`** 把轨迹分成高/低速后统计了每条轨迹包含的帧数（即“在视野中持续的帧数”）：

- **低速轨迹**：平均 **≈19.7 帧**，中位数 **14 帧**，范围 **5–198 帧**  
- **高速轨迹**：平均 **≈8.8 帧**，中位数 **7 帧**，范围 **5–42 帧**

所以大致上：**高速微泡在视野中出现的帧数更短（约 7–9 帧），低速的更长（约 14–20 帧）**。

轨迹密度不是“把每条轨迹画成线”，而是**把所有轨迹点累加成“访问频次图”**。简单说：每个轨迹点在网格上 +1，最后得到“哪个位置被轨迹经过得多”的密度图。

核心步骤（在 tracking 模块里完成）：
- 每条轨迹是一串点；对每个点在超分辨率网格上累加（`SUPER_RES_FACTOR` 放大网格）。  
- 累加后再做一次高斯平滑，让密度图更连贯。  
- 最后按 99 分位做归一化上色输出。

所以：**轨迹确实是短线，但密度图展示的是“点的堆叠频率”，不是单条轨迹本身**。很多短线叠加后，才会形成血管状的密度结构。

实现位置见 ulm_tracking.py。
