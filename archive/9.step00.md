# Step00 TIC 稳定连续窗口

日期：2026-06-15

## 当前定位

`step00_preprocess.py` 是 DICOM 到标准算法输入的唯一推荐入口。它负责：

```text
读取完整 DICOM
处理颜色空间
裁剪 ROI
计算完整源帧 TIC
选择连续稳定造影窗口
保存 frames.npy 和 metadata.json
```

推荐命令：

```bash
.venv/bin/python step00_preprocess.py --kind human --run-full-pipeline --sample 21.0
.venv/bin/python step00_preprocess.py --run-full-pipeline --sample <sample_id>
.venv/bin/python step00_preprocess.py --mask-only --sample <sample_id>
.venv/bin/python step00_preprocess.py --summarize-healthy-runs
```

三个常用入口分别对应：

```text
--mask-only
  给单个 DICOM 交互式画 cortex/exclude mask，不执行 Step05 计数。

--run-full-pipeline
  对已经有 cortex/exclude mask 的指定样本跑 Step00-05，并把 Step05 summary 写入 archive/healthy_step05_runs/。
  如果缺 mask 会直接报错；先用 --mask-only。
  Step00 会启用高增强 TIC 约束，先排除窗口均值低于 baseline->peak 增强幅度 45% 的稳定尾段。

--summarize-healthy-runs
  汇总 archive/healthy_step05_runs/ 内所有样本 JSON，生成 global_arguments.json，
  并把每个样本 JSON 改成“全局参数效果 + 最接近 450 的参数”两部分格式。
```

## 输出

```text
human_dcm/step00_preprocess/frames.npy
human_dcm/step00_preprocess/metadata.json
human_dcm/step00_preprocess/tic_raw.npy
human_dcm/step00_preprocess/tic_selection.png
human_dcm/step00_preprocess/selected_ranges.json
human_dcm/step00_preprocess/preview_frame_000.png
human_dcm/step00_preprocess/step00_mean_projection.npy
human_dcm/step00_preprocess/step00_mean_projection.png
human_dcm/step00_preprocess/step00_max_projection.npy
human_dcm/step00_preprocess/step00_max_projection.png
human_dcm/step00_preprocess/step00_std_projection.npy
human_dcm/step00_preprocess/step00_std_projection.png
```

`frames.npy[0]` 对应 `metadata.json["source_frame_indices"][0]`。后续 Step01-05 不直接读取源 DICOM。

`step00_mean/max/std_projection` 是对 Step00 选中的连续窗口做时间聚合得到的背景图：

```text
mean projection = 选中帧逐像素平均
max projection  = 选中帧逐像素最大值
std projection  = 选中帧逐像素标准差
```

这些 projection 的 `.npy` 是真实数值背景，`.png` 是无坐标轴、无 colorbar 的人工预览图。

## TIC 定义

TIC 是 time-intensity curve，当前只在已有 cortex mask 的 full pipeline 中计算。

有 cortex mask：

```text
TIC[源帧号] = ROI 中 cortex mask 内像素的平均 CEUS score
```

没有 cortex mask：

```text
不计算 TIC；Step00 使用 --start-frame/--frame-count 指定的手动窗口
```

Step00 会从 `--mask-dir` 读取 `cortex_mask.npy`。全流程样本模式默认读取：

```text
all_masks/<sample_id>/cortex_mask.npy
```

普通单步模式默认查找：

```text
masks/cortex_mask.npy
```

若 mask 是 Step04 的 4 倍超分辨率尺寸，Step00 会下采样到 Step00 帧尺寸后计算 TIC。

## 选帧逻辑

当前不再使用：

```text
默认前 600 帧
按总帧数百分比取窗口
early + late 两段拼接
```

当前流程：

```text
完整源 DICOM
-> 完整 TIC
-> moving average 平滑
-> 用开头 baseline_seconds 秒估计 baseline
-> baseline + min_enhancement 得到增强阈值
-> 枚举固定长度连续窗口
-> 选择增强足够且 TIC 更稳定的窗口
```

默认参数在 `step00_preprocess.py` 顶部：

```text
DEFAULT_TARGET_FRAMES = 401
DEFAULT_MIN_FRAMES = 1
DEFAULT_SMOOTH_WINDOW = 15
DEFAULT_BASELINE_SECONDS = 2.0
DEFAULT_MIN_ENHANCEMENT = 0.01
```

命令行覆盖：

```bash
.venv/bin/python step00_preprocess.py \
  --kind human \
  --target-frames 400 \
  --min-frames 300 \
  --smooth-window 21 \
  --baseline-seconds 2.0 \
  --min-enhancement 0.01
```

窗口评分主要考虑：

```text
TIC 标准差越小越好
窗口首尾 drift 越小越好
低于 baseline + min_enhancement 的比例越小越好
未指定 target_tic 时，轻微偏好更高的增强强度
指定 target_tic 时，窗口均值越接近该 TIC 越好
```

## metadata 关键字段

```json
{
  "frames_saved": 200,
  "source_frame_start": 200,
  "source_frame_end_exclusive": 400,
  "source_frame_end_inclusive": 399,
  "source_frame_indices": [200, 201],
  "selected_source_frames": [200, 201],
  "frame_selection_method": "tic_absolute_stable_window",
  "selected_ranges": {
    "selected_start": 200,
    "selected_end": 399
  },
  "frame_selection_parameters": {
    "target_frames": 200,
    "min_frames": 200,
    "smooth_window": 15,
    "baseline_seconds": 2.0,
    "min_enhancement": 0.01,
    "target_tic": null
  },
  "tic_mask": {
    "mode": "cortex_mask"
  }
}
```

`source_frame_end_exclusive` 遵循 Python 切片语义，不包含该帧。`source_frame_end_inclusive` 是实际保存的最后一帧源 DICOM 编号。

## 颜色空间处理

部分 DICOM 标签写的是 RGB，但 JPEG/JFIF codestream 实际提示 YBR。当前 `ulm_io.py` 不直接忽略 pydicom warning，而是：

```text
检测 RGB tag + JFIF YBR codestream
用 raw=True 读取原始像素
按 YBR_FULL_422 -> RGB 显式转换
把处理记录写入 metadata["color_space_handling"]
```

这样可以避免颜色解释错误影响 CEUS score。

## 全流程样本模式

命令：

```bash
.venv/bin/python step00_preprocess.py --kind human --run-full-pipeline --sample 21.0
```

目录约定：

```text
all_masks/21.0/21.0.dcm
all_masks/21.0/cortex_mask.npy
all_masks/21.0/exclude_mask.npy
```

执行顺序：

```text
解析或登记样本
检查 all_masks/<sample_id>/cortex_mask.npy 和 exclude_mask.npy 必须存在
清理 human_dcm 当前 Step 输出
Step00
  使用 cortex mask 内 TIC，并启用高增强窗口约束
Human rapid/slow Step01-04
Step05 count
保存 archive/healthy_step05_runs/<sample_id>_summary.json
```

常用选项：

```bash
.venv/bin/python step00_preprocess.py \
  --kind human \
  --run-full-pipeline \
  --sample 21.0 \
  --count-mode healthy_calibration
```

病肾/未知样本使用固定公共参数：

```bash
.venv/bin/python step00_preprocess.py \
  --kind human \
  --run-full-pipeline \
  --sample disease_01 \
  --count-mode diagnostic \
  --dbscan-eps-mm <healthy_common_eps>
```

## 汇总健康样例全局参数

健康样例跑完 Step05 后，每个样本会在 `archive/healthy_step05_runs/` 下留下一个 JSON：

```text
archive/healthy_step05_runs/11.0_summary.json
archive/healthy_step05_runs/21.0_summary.json
archive/healthy_step05_runs/5.0_summary.json
```

用 Step00 的汇总入口生成全局参数报告：

```bash
.venv/bin/python step00_preprocess.py --summarize-healthy-runs
```

默认输出：

```text
archive/healthy_step05_runs/global_arguments.json
```

同时默认会把每个 `<sample_id>_summary.json` 改成两部分格式：

```text
part1_global_parameters_effect
  全局参数下的估计效果。
  最重要字段：
    effect.glomeruli_count

part2_closest_to_450_parameters
  该样本自身扫描中，计数最接近健康肾小球数量 450 的参数。
  最重要字段：
    parameters.dbscan_eps_mm
    effect.glomeruli_count
    effect.distance_to_target
```

当前全局参数的定义：

```text
1. 从所有健康样本的 sampled_counts 中枚举公共 dbscan_eps_mm 候选。
2. 优先选择能让所有样本 global_count >= --healthy-min-count 的候选，默认下限 400。
3. 若存在同时不超过 --healthy-max-count 的候选，优先使用；否则把超上限作为软惩罚。
4. 对候选的跨样本 count 向量做 PCA，用到 target-count 向量的 PCA 距离、target gap 和离散度选择不过高的公共 eps。
5. 对每个样本，用 global_parameters.dbscan_eps_mm 在该样本 sampled_counts 里找最近 eps 的 count，作为全局参数下的估计效果。
```

如果只想生成 `global_arguments.json`，不重写每个样本 JSON：

```bash
.venv/bin/python step00_preprocess.py \
  --summarize-healthy-runs \
  --no-rewrite-healthy-json
```

如果目标健康肾小球数不是 450，可以指定：

```bash
.venv/bin/python step00_preprocess.py \
  --summarize-healthy-runs \
  --healthy-target-count 450
```

也可以显式指定全局计数约束：

```bash
.venv/bin/python step00_preprocess.py \
  --summarize-healthy-runs \
  --healthy-min-count 400 \
  --healthy-max-count 600
```

## 单独给指定 DICOM 打 mask

如果 `all_masks/` 根目录里有未打 mask 的单独 DICOM，例如：

```text
all_masks/9.0.dcm
all_masks/19.0.dcm
all_masks/25.0.dcm
```

使用 `mask-only` 入口：

```bash
.venv/bin/python step00_preprocess.py --kind human --mask-only --sample 9.0
```

也可以直接指定 DICOM 路径：

```bash
.venv/bin/python step00_preprocess.py \
  --kind human \
  --mask-only \
  --dicom all_masks/9.0.dcm
```

该入口只负责准备 mask，不执行 Step05 计数。执行顺序：

```text
解析 sample_id，例如 9.0.dcm -> 9.0
清理 human_dcm 当前 Step 输出
Step00
Human rapid/slow Step01-04
调用 Step05 交互式 polygon 工具重画 cortex/exclude mask
保存 mask 到 all_masks/9.0/
把 all_masks/9.0.dcm 收进 all_masks/9.0/9.0.dcm
```

画 mask 的背景选择：

```text
cortex mask:
  默认使用 human_dcm/step00_preprocess/step00_mean_projection.npy
  原因是 cortex mask 要圈解剖边界，不能依赖 slow density 这种算法产物。

exclude mask:
  优先使用 human_dcm/step04_density_metrics/human_density_profile_overlay.png
  其次使用 human_density_total.png 或 human_density_rapid.png
  如果 Step04 density 太弱，则回退到 step00_mean_projection.npy
```

因此，第一次给未标注 DICOM 打 mask 时，即使 slow density 很稀疏，也不会再用几乎全黑的 slow density 作为 cortex 背景。

保存后的目录结构：

```text
all_masks/9.0/
├── 9.0.dcm
├── cortex_mask.npy
├── cortex_mask_overlay.png
├── cortex_mask.log.json
├── exclude_mask.npy
├── exclude_mask_overlay.png
└── exclude_mask.log.json
```

交互式画 mask 时：

```text
鼠标点击多边形顶点
Enter 完成当前 polygon
直接空 Enter 保存并退出当前 mask
```

`--mask-only` 总是重新绘制 cortex/exclude mask。即使 `all_masks/9.0/` 里已经存在旧的
`cortex_mask.npy` 或 `exclude_mask.npy`，新结果也会覆盖旧文件；这个入口不提供跳过已有
mask 的分支。

默认 `mask-only` 会清理 `human_dcm/` 当前 Step 输出，保证中间结果只代表当前 DICOM。如需保留旧输出用于对比：

```bash
.venv/bin/python step00_preprocess.py \
  --kind human \
  --mask-only \
  --sample 9.0 \
  --keep-existing-outputs
```
